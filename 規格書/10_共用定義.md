# 10　共用定義

版本 v4.1（2026-11-05）｜開發者（含 Claude Code）必讀

本篇定義**各功能共用**的程式名稱、資料、服務與事件。其他規格書描述「要做什麼」，本篇規定「大家用同一套東西做」。任何功能都不得自行另做一套與本篇重複的東西。

閱讀說明：反引號中的英文（例如 `Wallet`）是程式裡的名稱，旁邊的中文是它的意思。

---

## 第一章　程式結構

沿用現有的單一模組 `economycore`，套件根目錄 `com.chair.economycore`。新增 `service` 資料夾放共用服務。

| 資料夾 | 放什麼 |
| --- | --- |
| `service` | 本篇第三章的所有共用服務（新增） |
| `event` | 本篇第四章的共用事件，以及 Forge 事件監聽 |
| `data` | 存在世界存檔裡的資料（本篇第五章） |
| `capability` | 存在玩家身上的資料（本篇第五章） |
| `config` | 讀取 `economy.toml` 與各 JSON 設定檔 |
| `network` | 玩家端與伺服器之間的訊息 |
| `util` | 共用列舉（本篇第二章）與小工具 |
| `core` | 各功能的清單資料（懸賞、地圖畫圖案等） |
| `block`、`item`、`entity`、`screen`、`command` | 方塊、物品、NPC、介面、指令 |

**唯一規則**：功能之間只能透過 `service` 互相呼叫，不得直接讀寫別的功能的資料。例如懸賞完成要給錢，只能呼叫 `Wallet`，不能直接改玩家的錢包資料。

## 第二章　共用列舉

列舉＝固定選項的清單。存檔裡一律存**英文名稱**（不是第幾個），所以只能新增、不能改名。

### 2.1 時代 `Era`

| 程式名稱 | 中文 | 順序 |
| --- | --- | --- |
| `PIONEER` | 拓荒時代 | 0 |
| `SETTLEMENT` | 開墾時代 | 1 |
| `COMMERCE` | 商業時代 | 2 |
| `AETHER` | 天穹時代 | 3 |
| `STAR` | 星辰時代 | 4 |

提供「是否已達某時代」的判斷 `isAtLeast(Era)`。舊存檔中的 `INDUSTRY`（工業時代）讀取時轉為 `COMMERCE`。

### 2.2 冒險者階級 `AdventurerRank`

`F`、`E`、`D`、`C`、`B`、`A`、`S`，門檻讀 `rank.thresholds`。

| `CLERIC` | 牧師 |

用於懸賞的「相關職業」與公會的「親近職業」。

## 第三章　共用服務

服務＝一組「其他功能只能透過它來做某件事」的功能。以下列出每個服務提供的動作；程式中的方法名稱放在括號內。

### 3.1 錢包 `Wallet`（〈01〉第一章）

| 動作 | 說明 |
| --- | --- |
| 查餘額（`balance`） | 回傳整數希爾 |
| 加錢（`deposit`） | 參數：玩家、金額、事由、細節文字。金額 ≤ 0 不動作。自動記帳、同步給玩家 |
| 嘗試扣錢（`tryWithdraw`） | 同上；餘額不足時回傳失敗且不扣錢 |
| 設定餘額（`adminSet`） | 只給管理員指令用，事由固定 `ADMIN` |

### 3.2 帳本 `Ledger`

| 動作 | 說明 |
| --- | --- |
| 記一筆（`record`） | 只由 `Wallet` 呼叫，其他功能不直接呼叫 |
| 期間報表（`report`） | 給 `/economy report` 用 |
| 個人最近紀錄（`recent`） | 給古代石碑「帳本」頁用 |

### 3.3 模組日 `ModCalendar`（〈01〉第二章）

| 動作 | 說明 |
| --- | --- |
| 今天是第幾天（`today`） | 整數，從 0 開始 |
| 本週第幾天（`dayOfWeek`）、第幾週（`week`） | 7 天一週 |
| 換日時 | 送出 `DayChangedEvent`（第四章） |

所有「每日」「每週」的規則一律用它，**不得**直接讀遊戲世界時間。

### 3.4 人數係數 `PlayerScale`（〈00〉第五章）

| 動作 | 說明 |
| --- | --- |
| 活躍人數（`activeCount`） | 最近 7 個模組日登入過的不同玩家數，至少 1 |
| 人數係數（`scale`） | 0.15～1.0 |
| 依係數縮放（`scaled(數值)`） | 數值 × 係數 |

### 3.5 物品估價 `ItemValues`（〈02〉第一章）

| 動作 | 說明 |
| --- | --- |
| 單價（`valueOf`） | 依物品堆疊（含耐久）回傳 V，小數 |
| 物品族（`familyOf`） | 回傳物品所屬的物品族（〈02〉1.6） |
| 可否回收（`isRecyclable`） | 檢查拒收名單、V > 0、容器是否有內容物 |
| 說明（`explain`） | 回傳 V 與物品族是怎麼算出來的，給 `/economy value` 用 |
| 重新計算（`rebuild`） | 啟動與 `/economy reload` 時呼叫 |

### 3.6 交易稅 `SaleTax`（〈03〉第六章）

| 動作 | 說明 |
| --- | --- |
| 試算（`quote`） | 參數：玩家、稅前金額。回傳稅額，不改任何資料 |
| 結算（`apply`） | 計稅、累加今日賣出總額、經 `Wallet` 以 `SALE_TAX` 扣除稅額、回傳實得金額。呼叫前稅前金額必須已存入錢包 |

公會天賦的減免由 `SaleTax` 向公會服務查詢，沒有公會功能時視為無減免。

### 3.7 回收 `RecycleService`（〈02〉第二、三章）

| 動作 | 說明 |
| --- | --- |
| 報價（`quote`） | 參數：玩家、物品、數量、管道。回傳稅前金額、行情百分比、受每日上限影響後可賣數量 |
| 賣出（`sell`） | 執行收購：扣物品、更新物品族的近期回收量 A、更新每日已用額度、經 `Wallet` 存入稅前金額、再呼叫 `SaleTax.apply` 扣稅 |

### 3.8 時代 `EraService`（〈03〉第一章）

| 動作 | 說明 |
| --- | --- |
| 目前時代（`current`）、是否已達（`isAtLeast`） | — |
| 進度（`progress`） | 四類條件的目前值與需求值 |
| 捐物（`donateItems`）、捐錢（`donateCiel`） | 集資箱呼叫 |
| 記錄里程碑（`markMilestone`） | 進入地獄、擊敗終界龍、擊敗凋零怪時呼叫 |
| 檢查晉升（`checkAdvance`） | 每次捐獻、里程碑、階級變化後呼叫；晉升時送出 `EraChangedEvent` |

### 3.9 階級 `RankService`

| 動作 | 說明 |
| --- | --- |
| 查 RP 與階級（`rp`、`rank`） | — |
| 加 RP（`addRp`） | 參數：玩家、數量、原因。套用公會 RP 加成後再加 |
| 扣 RP（`removeRp`） | 限時懸賞逾時用 |
| 全服達到某階級的人數（`countAtLeast`） | 給時代條件用 |

### 3.10 小工具 `Util`

| 名稱 | 說明 |
| --- | --- |
| 給物品（`giveOrDrop`） | 放進背包，放不下的掉在玩家腳下。**所有給玩家物品的地方都必須用它** |
| 介面守門（`MenuGuard.check`） | 伺服器收到介面請求時確認：玩家開著指定介面、距離在 `ui.maxDistance` 內。不通過就忽略請求 |
| 時代閘門（`EraGate.require`） | 時代未到時顯示「需要 ○○ 時代」並回傳失敗 |
| 金額取整（`Money.round`） | 規則見第六章 |

## 第四章　共用事件

事件＝某件事發生時「廣播」給所有想知道的功能。發出事件的功能不需要知道誰在聽。

| 事件 | 何時發出 | 內容 | 誰會聽（舉例） |
| --- | --- | --- | --- |
| `DayChangedEvent` | 模組日 +1 時 | 新的日數 | 回收量回升、捐獻 D 回復、交易所庫存回歸、投機品更換、懸賞重抽、持有稅（每 7 日） |
| `EraChangedEvent` | 時代晉升時 | 舊時代、新時代 | 廣播訊息、NPC 與設施解鎖 |
| `BountyCompletedEvent` | 懸賞回報成功時 | 玩家、懸賞 ID、RP、相關職業 | 公會經驗、時代條件檢查 |
| `RankChangedEvent` | 玩家階級改變時 | 玩家、舊階級、新階級 | 時代條件檢查、界碑石上限 |
| `ItemFirstSeenEvent` | 本世界第一次有玩家撿起某物品時 | 物品 | 自動生成懸賞的候選清單 |

## 第五章　資料儲存

### 5.1 存在玩家身上（玩家資料，死亡保留）

| 資料 | 內容 |
| --- | --- |
| 錢包 | 餘額 |
| 信譽 | RP、懸賞進度、今日抽樣結果 |
| 每日計數 | 今日回收已用額度、今日投機品各物品數量與收入、今日交易所各品項買賣數量、今日交易所賣出收入、今日賣出總額（計稅用）、今日回城次數、急救冷卻、今日是否已領祝福 |
| 收藏 | 博物館已收錄物品（第二階段） |
| 界碑石 | 位置與名稱清單（第二階段） |

**每日計數的寫法**：每個計數都附上「這是第幾天的數字」，讀取時若日數不是今天就視為 0。不需要在換日時逐一清空。

### 5.2 存在世界存檔（全服共用，放在主世界的資料儲存區）

| 資料檔名 | 內容 |
| --- | --- |
| `ecosuite_calendar` | 目前模組日、上次記錄的世界時間 |
| `ecosuite_players` | 每位玩家最後登入的模組日（算活躍人數） |
| `ecosuite_era` | 目前時代、本時代已累積的文明點數與捐獻希爾、已達成的里程碑 |
| `ecosuite_donation` | 每個物品族的累計捐獻價值 D |
| `ecosuite_recycle` | 每個物品族的近期回收量 A |
| `ecosuite_exchange` | 各品項庫存 |
| `ecosuite_speculation` | 兩個投機品欄位的物品與到期日、各物品冷卻 |
| `ecosuite_seen_items` | 本世界被撿起過的物品清單 |

帳本不存在世界存檔，另存為 `世界資料夾/economycore/ledger/day_N.csv`（N 為模組日），方便用試算表或文字編輯器打開。

### 5.3 存檔版本與轉換

- 每份資料都記錄 `dataVersion`（資料版本）。
- 讀到舊版本時依下表轉換，轉換後以新版本存檔：

| 從 | 轉換 |
| --- | --- |
| 時代 `INDUSTRY` | 轉為 `COMMERCE` |
| 舊的文明點數總數 | 視為「本時代已累積文明點數」 |
| 舊的 `ecosuite_world_progression` 中各物品捐獻數量 | 乘以該物品的 V 後，累加到所屬物品族的 D |
| 舊的黑市、交易所每日資料 | 捨棄（每日資料，不影響進度） |

## 第六章　數值與取整

| 規則 | 說明 |
| --- | --- |
| 希爾 | 一律整數 |
| V、文明點數、近期回收量、累計捐獻 | 小數 |
| 計算順序 | 全部用小數算完，最後才取整 |
| 取整方向 | 玩家**收到**的錢無條件捨去；玩家**付出**的錢無條件進位 |
| 數值來源 | 所有數值讀 `economy.toml` 或 JSON（〈08〉），程式中不得出現規格裡的數字（0、1 這類非規則數字除外） |

## 第七章　玩家端與伺服器

| 規則 | 說明 |
| --- | --- |
| 伺服器說了算 | 所有價格、扣款、給物品都在伺服器計算 |
| 報價 | 介面需要顯示價格時，向伺服器要報價，不在玩家端自己算（避免玩家端的設定不同而顯示錯誤） |
| 清單同步 | 懸賞、商店、交易所品項、投機品，在登入與 `/economy reload` 時由伺服器傳給玩家端 |
| 請求內容 | 用物品名稱（例如 `minecraft:diamond`）或懸賞 ID 指定對象，不用「第幾行」 |
| 守門 | 每個請求都先經過 `MenuGuard.check` |

## 第八章　文字

- 玩家看得到的文字一律寫在語言檔 `zh_tw.json`，程式中只放翻譯鍵；並附一份英文 `en_us.json`（可先與中文鍵相同，之後再補翻譯）。
- 介面文字只寫功能資訊（物品名、價格、數量、狀態、操作），不加旁白或帶語氣的說明。
- 滑鼠停留說明（tooltip）可以寫規則說明，但用平鋪直敘的句子。
